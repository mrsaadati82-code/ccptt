▣ معماری کلی
─────────────────────────────────────────────────────────────────────────────
- پلاگین وردپرس مادر: «هماهنگ پرو» (Client Project Tracker / CPTT)
  که شامل: مدیریت پروژه‌ها، کارشناسان، مشتریان، فاکتورها، تسویه، چت AI،
  یادآور، Bale notifications، WooCommerce integration و …
- پنل ERP در صفحه‌ی WordPress: admin.php?page=cptt-finance-erp
- React 19 + Tailwind v4 + TypeScript + Vite (single-file bundle ≈ 410KB)
- اتصال زنده به دیتابیس واقعی پلاگین از طریق ۳۰+ AJAX endpoint
- تقویم شمسی native در همه فیلدهای تاریخ
- چندارزی: تومان، ریال، USD، EUR (تبدیل خودکار)
- ۴ نقش کاربری: صندوق‌دار، حسابدار، مدیر مالی، مدیرعامل
- Toast notification برای هر عملیات
- Pagination، Accordion، Search، Filter در هر بخش

  سود ناخالص، موجودی خزانه، پروژه‌های باز، پروژه‌های تسویه‌شده

[ 3 ] اسناد حسابداری (Vouchers)

- KPI: کل اسناد، پیش‌نویس، در حال تأیید، نهایی‌شده
- فیلتر: همه / بر اساس وضعیت / جستجو در شماره و شرح
- pagination ۱۰ تایی

عملیات (با AJAX):

[ 4 ] دفاتر و گزارشات مالی
─────────────────────────────────────────────────────────────────────────────
زیرمنوهای داخلی با Tabs (کاملاً سریع و local):

  4.1 دفتر روزنامه (Journal)
    - نمایش flat تمام ردیف‌های همه‌ی اسناد
    - ستون‌ها: تاریخ، شماره سند، شرح، حساب، بدهکار، بستانکار
    - جمع کل (با فیلتر فعال)
    - جستجو + pagination ۱۵ تایی

  4.2 دفتر کل (General Ledger)
    - گردش حساب‌های "کل" (انتخاب از dropdown)
    - نمایش جمع بدهکار/بستانکار/مانده
    - تمام تراکنش‌های مرتبط با آن حساب

  4.3 دفتر معین (Subsidiary Ledger)
    - مشابه دفتر کل ولی برای حساب‌های معین

  4.4 تراز آزمایشی (Trial Balance)
    - جدول کامل: کد، نام، گردش بدهکار، گردش بستانکار، مانده، نوع (بد/بس)
    - چک تراز بودن (جمع بدهکار = جمع بستانکار)

  4.5 صورت سود و زیان (Income Statement)
    - مجموع درآمدها (حساب‌های کد ۵)
    - مجموع هزینه‌ها (حساب‌های کد ۶)
    - سود/زیان ویژه = درآمد − هزینه

  4.6 ترازنامه (Balance Sheet)
    - دارایی‌ها (کد ۱ و ۲)
    - بدهی‌ها (کد ۳)
    - حقوق صاحبان سهام (کد ۴)
    - چک معادله: دارایی = بدهی + سرمایه

عملیات: فقط نمایشی (محاسبات from voucher rows)

- KPI: جمع درآمد، جمع هزینه، مانده خالص، تعداد رکورد
- فیلتر: همه/درآمد/هزینه + بر اساس حساب + بر اساس پروژه + جستجو
- pagination ۱۵ تایی
- modal ثبت تراکنش جدید با: نوع، عنوان، مبلغ، تاریخ شمسی (با datepicker)،
  حساب، دسته (از category list)، پروژه، توضیحات

عملیات (با AJAX):
- cpttf_erp_ie_save → ذخیره تراکنش در wp_cptt_fin_ledger
- cpttf_erp_ie_delete → حذف تراکنش

[ 6 ] تسویه کارشناسان (Expert Settlement)
─────────────────────────────────────────────────────────────────────────────
- لیست کارشناسان با نمایش مطالبات و تسویه‌شده
- انتخاب کارشناس → نمایش مراحل قابل تسویه (PENDING) با امکان انتخاب چندتایی
- جمع مبلغ انتخابی به‌صورت زنده محاسبه می‌شود
- انتخاب حساب پرداخت + توضیحات → ثبت تسویه
- KPI: مجموع مطالبات، مجموع تسویه‌شده، تعداد کارشناسان
- modal پرداخت دستی (off-stage payment): کارشناس، مبلغ، حساب، توضیحات
- جدول تاریخچه ۲۰ تسویه آخر

اتوماسیون با هسته پلاگین:
- ثبت تسویه → روی _cptt_steps پروژه (expert_paid, settled)
- trigger هوک cptt_after_expert_payout → نوتیف Bale + activity log + ledger
- ثبت پرداخت دستی → CPTT_Core::ledger_add با expert_manual_payout
- hook cptt_after_manual_expert_payment trigger می‌شود
- در داشبورد کارشناس و حساب پروژه‌ها بازتاب پیدا می‌کند

عملیات (با AJAX):
- cpttf_erp_settle_steps → تسویه چندمرحله‌ای
- cpttf_erp_settle_manual → پرداخت دستی

▶ امکانات مفقود حسابداری استاندارد:
1. اسناد افتتاحیه و اختتامیه خودکار سال مالی
2. تجمیع و گزارش‌گیری چندشرکتی (consolidation)
3. تخصیص هزینه‌ها به مراکز هزینه (cost allocation)
4. گزارش جریان وجوه نقد (Cash Flow Statement)
5. گزارش تغییرات حقوق صاحبان سهام
6. صورت‌حساب بدهکار/بستانکار (Statement of Account) برای هر مشتری/کارشناس
7. اعتبارسنجی سند: چک خودکار اینکه حساب باید detail یا subsidiary باشد
8. سند چندارزه با محاسبه تفاوت تسعیر ارز (FX gain/loss)
9. درج خودکار سند هنگام دریافت پول از مشتری (الان فقط ledger می‌نویسد)
10. خط مشی شماره‌گذاری: prefix بر اساس نوع سند

▶ امکانات مفقود گزارش‌گیری:
1. Export به Excel/PDF/CSV
2. Print preview با header شرکت + dates
3. مقایسه دوره‌ای (year-over-year)
4. نمودار جریان نقد ماهانه
5. سن مطالبات (Aging Report) — 30/60/90 روز
6. سودآوری هر پروژه با حاشیه سود

        │
        ├─ پیشخوان وردپرس (پروژه‌ها، کارشناسان، فاکتورها، …)
        │   └─ پلاگین CPTT (هماهنگ پرو) — کلاس‌های PHP اصلی
        │       ├─ wp_posts (cptt_project)
        │       ├─ wp_postmeta (_cptt_steps, _cptt_client_user_id, …)
        │       ├─ wp_users (نقش cptt_expert)
        │       ├─ wp_cptt_ledger (تسویه کارشناسان)
        │       ├─ wp_cptt_fin_accounts (حساب‌های خزانه)
        │       ├─ wp_cptt_fin_ledger (تراکنش‌های مالی)
        │       └─ wp_cptt_fin_categories (دسته‌ها)
        │
        └─ پنل ERP (admin.php?page=cptt-finance-erp)
            ├─ admin_init: حذف admin bar + admin menu + notices
            ├─ dequeue_3rd_party_assets: فقط Tailwind/React را اجازه می‌دهد
            ├─ enqueue: app.js (React 19 + Tailwind v4) + app.css
            ├─ bootstrap window.CPTTF_ERP: { nonce, user, urls, … }
            └─ React app mount روی <div id="root">
                ├─ AppContext: hydrate از سرور با cpttf_erp_full_bootstrap
                ├─ Sidebar + Navbar + Content
                ├─ هر mutation → wpApi.X → endpoint سرور → reload → toast
                └─ هوک‌های پلاگین (cptt_after_expert_payout, …) trigger می‌شوند
                   پس Bale notif + activity log + ledger auto-update می‌شود
