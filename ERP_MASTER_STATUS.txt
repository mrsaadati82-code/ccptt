─────────────────────────────────────────────────────────────────
  ۵) فازهای بعدی (به ترتیب اولویت)
─────────────────────────────────────────────────────────────────

  ▶ فاز ۹ — اتصال backend به React  (خیلی مهم)
    نسخه هدف: ۸.۱.۰
    کارها:
    • ذخیره‌ی source های React تا بشود دوباره ساخت
    • اتصال ۸۰ تا API ساخته‌شده به پنل React
    • رفع اعلانات دوگانه
    • رفع ledger دوگانه برای پرداخت کارشناس
    • چک و فاکتور هم به ledger وصل شوند

  ▶ فاز ۱۰ — تب‌های جدید در پنل React  (مهم)
    نسخه هدف: ۸.۲.۰
    کارها:
    • اضافه کردن ۶ تب جدید به پنل (نگاشت حساب، بستن سال،
      گزارش‌های پیشرفته، عملیات، یکپارچه‌سازی، فاکتورها)
    • دکمه‌های چاپ در صفحات React
    • Aging دقیق با تاریخ پرداخت آخر
    • بستن سال مالی واقعی در React

  ▶ فاز ۱۱ — تجربه‌ی کارشناس و مشتری  (مهم برای کسب‌وکار)
    نسخه هدف: ۸.۳.۰
    کارها:
    • صفحه کارشناس → نمایش KPI مالی شخصی (مانده تسویه، تاریخچه)
    • صفحه مشتری → نمایش KPI مالی (بدهی، پروژه‌ها، آخرین پرداخت)
    • اتصال فاکتور به پروژه

  ▶ فاز ۱۲ — ساخت ماژول CRM  (بزرگ)
    نسخه هدف: ۹.۰.۰
    کارها:
    • لید (مشتری بالقوه)
    • فرصت فروش (Pipeline)
    • تاریخچه ارتباطات
    • گزارش برد/باخت


─────────────────────────────────────────────────────────────────
  ۶) مشکلات شناخته‌شده (مرتب‌شده از مهم‌ترین)
─────────────────────────────────────────────────────────────────

  🔴 خیلی مهم (باید قبل از هر کار جدید حل شود):
  
    M-۱  source های React پاک شده‌اند              ✅ حل شد (نسخه ۸.۰.۱)
         راه‌حل اجرا شد: پوشه‌ی جدید ui-src/ در ریشه پلاگین
         شامل scaffold + ۵ فایل util کلیدی (۸۱۵ خط)
         + script استخراج bundle
         در فاز ۹، AppContext + App + components اضافه می‌شود.

    M-۲  ۸۰ تا قابلیت در backend هست ولی در React نیست
         نتیجه: کاربر فکر می‌کند ERP این کارها را ندارد
         راه‌حل: فازهای ۹ و ۱۰ (الان زیرساخت آماده است)

    M-۳  ledger پرداخت کارشناس دوبار ثبت می‌شود (در دو جای متفاوت)
         نتیجه: عدد گزارش‌ها با هم فرق دارد
         راه‌حل: فاز ۹

  🟠 مهم:
  
    M-۴  دو سیستم اعلان جدا کار می‌کنند
         نتیجه: کاربر در دو جا اعلان می‌بیند
    
    M-۵  چک وقتی وصول می‌شود به ledger ثبت نمی‌شود
         نتیجه: تطبیق بانک اشتباه می‌شود
    
    M-۶  فاکتور وقتی به سند تبدیل می‌شود ledger ثبت نمی‌شود
    
    M-۷  کارشناس KPI مالی خودش را نمی‌بیند
    
    M-۸  صفحه مشتری KPI مالی ندارد
    
    M-۹  صفحه «سطوح دسترسی» در React مجوزهای جدید را نشان نمی‌دهد

  🟡 متوسط:
  
    M-۱۰ گزارش Aging دقیق نیست (تاریخ پرداخت آخر در data نیست)
    
    M-۱۱ دکمه «بستن سال مالی» در React الکی است
    
    M-۱۲ «گردش حساب یکپارچه» در React چک و قسط را نشان نمی‌دهد
    
    M-۱۳ React هنوز همه data را یکجا می‌گیرد (کند)


─────────────────────────────────────────────────────────────────
  ۷) صفحات یا دکمه‌هایی که داده ندارند
─────────────────────────────────────────────────────────────────

  مهم:
    • داشبورد کارشناس → KPI «درآمد ایجاد شده» وجود ندارد
    • داشبورد کارشناس → KPI «مانده تسویه» وجود ندارد
    • صفحه مشتریان → KPI «بدهی» وجود ندارد
    • داشبورد ERP → کلیک روی KPI کار نمی‌کند
    • پنل React → ۶ تب جدید فاز ۲ تا ۸ وجود ندارد
    • صفحه اسناد → دکمه «↻ برگشت سند» وجود ندارد
    • صفحه سال مالی → دکمه «بستن سال» الکی است

  متوسط:
    • صفحه مشتریان → تعداد پروژه‌ها نشان داده نمی‌شود
    • صفحه مشتریان → لینک «صورت‌حساب» وجود ندارد
    • صفحه اسناد → دکمه Unfinalize وجود ندارد

    🔵 هر بار که حتی یک تغییر کوچک در کد انجام شد:
         ۱. نسخه افزونه باید بالاتر برود (مثلاً ۸.۰.۰ → ۸.۰.۱)
            • تغییر کوچک (رفع باگ، توضیح، …) → آخرین رقم +۱
              مثال: ۸.۰.۰ → ۸.۰.۱
            • تغییر متوسط (قابلیت جدید کوچک) → رقم وسط +۱
              مثال: ۸.۰.۱ → ۸.۱.۰
            • تغییر بزرگ (فاز کامل، تغییر معماری) → رقم اول +۱
              مثال: ۸.۹.۰ → ۹.۰.۰
         
         ۲. در فایل client-project-tracker.php دو جا باید عوض شود:
            • خط Version: X.Y.Z
            • خط define('CPTT_VERSION', 'X.Y.Z')
         
         ۳. زیپ نصبی جدید با همان نسخه ساخته شود
         
         ۴. زیپ به سه مسیر کپی شود:
            • /home/user/client-project-tracker-X.Y.Z.zip
            • /home/user/ccptt/client-project-tracker-X.Y.Z.zip
            • /home/user/dist/client-project-tracker-X.Y.Z.zip
         
         ۵. زیپ نسخه قبلی پاک شود
         
         ۶. توی README.md توضیح کوتاهی از تغییرات اضافه شود

  ⚡ سایر قوانین:

    • هیچ کاری بدون اول بررسی کردن این فایل شروع نشود
    • هر قابلیت جدید باید این موارد را داشته باشد:
        - backend (PHP)
        - API (AJAX یا REST)
        - مجوز دسترسی (Permission)
        - ثبت در لاگ (Audit)
        - اعلان (اگر مربوط است)
        - اتصال به بخش‌های مرتبط
        - حداقل یک گزارش
        - حداقل یک KPI
        - KPI ها همیشه از داده‌ی واقعی، نه ثابت یا الکی
    
    • هر تراکنش مالی باید این موارد را به‌روز کند:
        - سند حسابداری (Voucher)
        - ledger
        - لاگ audit
        - اعلان مربوطه
        - گزارش‌های مرتبط
        - داشبوردها
    
    • هیچ طراحی جدید UI انجام نشود (طراحی موجود حفظ شود)
    • هیچ کتابخانه UI جدید نصب نشود
    • همه چیز Mobile-First، RTL و تقویم شمسی
    • هیچ قابلیت موجود حذف نشود (Backward Compatible)
